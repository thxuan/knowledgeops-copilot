# 文档版本、发布与权限说明

2026-10-18 首批实现。后续已增加账号模式、独立后台队列和工单闭环，更新说明见 [账号与后台业务](accounts-and-operations.md)。覆盖原文快照、草稿构建、显式发布、历史差异、以旧内容创建新版本、紧急撤回、实际 ACL 说明和更新记录。默认使用本地演示身份；自有账号模式见后续说明，不能据此宣称完成所有生产运维条件。

## 页面操作与搜索行为

进入 `/knowledge`，选择自己上传的文档。详情提供四个入口：

- 当前正文：当前版本及当前集合索引状态；上传新的 Markdown/TXT 完整原文，填写新版本标签和变更说明，保存草稿。
- 历史版本：查看原文件（含 front matter）与当前清洗正文的行差异；构建草稿索引；检查变更后提交审批，由平台管理员通过并发布。
- 访问权限：读者查看自己获权的原因；上传者查看该文档的三身份实际 ACL、修改授权。工单审核能力不自动授予知识阅读权限。
- 更新记录：快照、创建草稿、构建成功/失败、发布、撤回、授权前后变化，以及操作者和时间。

普通更新在发布前始终使用有效旧版。草稿和准备好的向量不会进入检索。发布将当前正文、词法切块头和当前集合的向量头在同一 PostgreSQL 事务中切换；检索和引用带新的版本标签。旧引用不再作为当前政策提供。其他集合须为新正文重建，不混用旧向量。

回滚使用“以此创建新版本”：例如以 v1 原文创建 v3，构建并发布。v2 及审计记录保留；文档 ACL 沿用当前授权，不恢复历史 ACL。为保留完整原文件，原文件内的 version 字段不会被重写，正式版本标签以页面和引用字段为准。

紧急撤回会立即移除当前检索入口，阻断当前引用访问和旧接口重建；读者列表隐藏该文档。上传者仍可管理、查看历史；重新创建草稿、构建、发布才恢复服务。撤回原因必填。发布、撤回校验 revision；构建后若其他人已发布/撤回，旧基线草稿不能覆盖新状态，需重新创建草稿。

## 历史与权限边界

上传者与当前组织的平台管理员具有历史阅读、差异和草稿维护能力；版本发布必须经过管理员审批，服务端同样校验。向读者开放当前正文不会开放历史或草稿，避免旧敏感正文因当前 ACL 放宽而泄露。其他普通读者通过版本 ID 或直接 URL 访问历史、回滚和构建仍返回不可见；普通读者无法查询其他身份的 ACL。

阅读当前正文仍需 document_access 中的直接授权。上传者即使撤销自己的阅读 ACL，也保留知识管理和历史查看能力，恢复阅读范围需提交审批；这不授予普通用户管理能力。当前获权原因不声称实现了动态组权限。

所有相关响应禁止浏览器缓存。页面切换身份时清空已读历史、原文与差异；后续请求重新鉴权。旧会话的当前证据校验仍沿用现有失效隐藏规则，没有把历史接口当作默认问答的后门。已经被合法复制的内容不能远程收回。

## 可重复演示 D01–D04

仅使用本目录的虚构政策；不要覆盖原来 14 份评测资料。

1. 上传 `sample_data/lifecycle-demo/policy-v1.md`，版本标签填 v1，构建草稿索引、提交审批，由管理员通过并发布。记录 document_id；提问“VPN 授权刷新需要多久？”，核对引用为 v1、事实为 15 分钟。真实问答需要有效聊天与 Embedding 配置。
2. 对同一文档点“上传新版本”，选择 policy-v2.md，标签 v2，说明“刷新从 15 分钟改为 5 分钟”。保存及构建后尚未发布，当前问答和引用继续使用 v1。历史页可以查看新增/删除行。
3. 提交发布审批，切换平台管理员通过并发布，再次同题提问，核对证据版本 v2 和 5 分钟；旧 v1 当前引用访问失败。生成措辞不作固定断言。
4. 选择 v1 的“以此创建新版本”，标签填 v3、说明写回滚原因，构建、提交审批并由管理员发布；三版历史保留，默认检索 v3。
5. 在发布申请中仅勾选工程师与普通员工，管理员审批通过后，切换普通员工可读当前正文且历史入口不可用；切换 IT 支持不应看到此文档。上传者可见实际矩阵。
6. 普通员工取回引用后，由上传者撤销该员工的 ACL；刷新、直接引用、检索与版本接口均不得再取回内容。上传者自撤权时管理能力单列，不用此分支冒充普通读者撤权。
7. 可选：构建草稿时用无效 Embedding 验证失败仍保留当前索引；修复连接后重试。紧急撤回则应立即停止当前内容服务。

重置：用上传者对该专用 document_id 调用 `DELETE /documents/{document_id}` 软删除；会保留其审计资料，因此重新演示请使用新的独立 schema，或使用含唯一演示编号的新文件，不尝试重复上传被删除的相同字节。不要清空共享 schema 或原有评测库。

## API 契约

均需当前本地身份头。下表路径前缀为 `/documents/{document_id}`。

| 路径 | 输入和用途 |
| --- | --- |
| `GET /versions` | 上传者或管理员读取不可变版本目录、当前 revision、构建状态及最近 100 条更新记录 |
| `POST /versions` | multipart：file、version、note、expected_revision；解析并保存草稿，201 |
| `GET /versions/{version_id}` | 上传者或管理员读取完整原文件与清洗正文；可用 compare_to 指定同文档另一版本作差异基线 |
| `POST /versions/{version_id}/build` | 现有切块参数 strategy/size/overlap；提交后台任务，202/job_id；真实 Embedding 准备产物，不发布 |
| `POST /versions/{version_id}/publish` | 兼容入口拒绝直接发布；请用发布审批 API |
| `POST /versions/{version_id}/restore` | JSON version、note、expected_revision；复制原文成为新草稿，不覆盖历史 |
| `POST /withdraw` | JSON expected_revision、reason；立即撤回 |
| `GET /access` | 当前身份阅读/管理/历史能力、获权原因；上传者和管理员收到完整用户 ACL |

原 `PUT /documents/{id}` 正文更新接口已停用，返回 `REVIEW_REQUIRED`。页面统一采用草稿与审批 API，详见 [文档发布审批](document-review.md)。

## 持久化与迁移

初始化幂等建立 document_versions、document_version_heads、document_version_builds 和 document_lifecycle_events，并从现存已解析正文建立第一个可验证快照。迁移时间明确标注为快照时间，不能冒充原始发布时间；既有旧切块无法恢复丢失的完整原文件。

当前页面通过持久后台队列构建草稿，返回 202/job_id；服务内或独立进程 worker 在页面关闭后继续执行，具体租约、取消、重试和配置恢复规则见后续说明。旧回调无法覆盖新产物。新集合/模型签名与准备产物不符时禁止发布，需重新构建。当前索引和文档须位于同一数据库和 search_path 才允许原子发布。

核心评测快照包含新增版本、构建产物、权限审计及事件序号，可隔离恢复。固定 14 篇样例备份仍只负责已审查样例，不是完整业务备份。数据库迁移框架、任务中心、企业 SSO/MFA、组权限、长期保留和生产备份演练继续参见生产路线图；自有账号和基础工单闭环已在后续实现。
