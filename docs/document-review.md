# 文档审阅与发布审批

上传者和当前组织的平台管理员可以查看草稿、原文、历史版本和差异。其他账号只能读取已发布且明确授权的正文，不能查看草稿或历史。管理员审阅权限限制在当前组织和所选知识空间内。

## 上传与首次发布

1. 使用日常工作账号上传文档，等待解析完成。此时文档为私有草稿。
2. 预览切分并构建索引。首次构建只准备草稿索引，不进入正式问答；可以通过批量构建提交后台任务。
3. 刷新文档，在“历史版本”中选择“提交发布审批”，勾选发布后的阅读账号并确认。
4. 平台管理员在知识库顶部的“文档发布审批”列表查看申请、原文与版本差异，核对阅读范围。
5. 点击“通过并发布”，或填写原因后点击“退回修改”。退回后上传者可以调整内容、重新构建并再次提交。

管理员自己上传的资料也经过显式提交和审批发布；当前没有强制双人分离，可以由同一管理员处理。普通账号不能通过伪造前端身份或直接调用发布接口绕过审批。

## 新版本与共享范围

- 新版准备、等待审批或被退回期间，已发布旧版继续提供检索。
- 审批绑定不可变的原文版本、当前修订号、索引产物和具体阅读账号，批准时再次检查模型和集合。
- 创建新草稿、重建待审索引、修改授权或撤回文档，会使相关待审批申请失效。重新提交后才能发布。
- 扩大共享范围需要审批；减少现有授权可在“访问权限”中立即保存。共享正文不会开放历史。
- 对已有草稿索引的当前版本，可使用“申请调整共享范围”；迁移来的历史资料没有草稿产物时，需先以原文创建新草稿并构建。
- 紧急撤回立即停止检索；恢复时创建新草稿并重新审批，不自动恢复历史授权。

审批通过时，在同一数据库事务中切换正文、切块、向量和阅读权限，并记录审批人、意见、时间和目标范围。重复或并发批准同一申请不会重复发布。

## 兼容与升级

首次升级时，已有当前切块指针的资料保留为已发布状态；未建立当前索引的旧上传标记为草稿。既有权限不自动扩大。各空间在应用启动或切换连接时执行幂等迁移。

旧的直接更新正文接口返回 `REVIEW_REQUIRED`，请改用版本草稿。新上传通过旧的直接索引入口不能发布；后台构建和同步工作台构建均转为准备草稿。离线资料导入也只准备私有草稿，其共享范围保留在来源 manifest，需后续审批。

本功能的验证使用独立临时数据库和离线模型替身，不调用付费模型。

## 批量提交审批

知识库列表勾选 1–100 份文档后，可点击“批量提交审批”。系统先检查草稿索引，列出每份要送审的版本和跳过原因，再统一选择发布后的阅读账号。L1 通用资料应选择普通员工、工程师和 IT 支持；每份上传者自动保留阅读权限。不同阅读范围的资料应分批提交。

已有待审申请会保留；未就绪、版本基线过期和已发布正文不会批量送审。多个可提交草稿需要明确选择版本。确认后逐份调用现有审批接口，逐项显示结果，支持停止后续项、继续和重试失败项。页面关闭会中断尚未提交项，已成功提交的申请保留。提交期间固定身份和工作空间，再次检查修订及索引状态；提交不会调用 Embedding，也不会自动审批或发布。管理员可逐份审阅，也可核对清单后批量通过。

## 管理员批量通过

平台管理员展开“文档发布审批 → 审批明细”，勾选或全选当前待审项，点击“批量通过”。每次最多 100 份，确认弹窗逐份展示文档版本、提交者和原有阅读范围，可填写统一审批意见。其他身份不显示批量审批入口，后端仍逐份校验平台管理权限。

点击“确认批量通过并发布”后，按固定身份、工作空间和具体审批 ID 逐份调用现有批准接口。各自的阅读范围保持申请中的设置；失效申请不会自动改批新申请。成功即发布并记录审批事件，单份失败不影响其余项，支持停止后续项、继续及重试失败项。重复批准沿用现有幂等校验；处理明细结束后自动收起。页面关闭会中断尚未处理项，已通过的申请保留。
