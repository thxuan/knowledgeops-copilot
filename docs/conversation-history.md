# 历史会话第一版

会话页增加可收起侧栏：最近会话、归档会话、分页加载、打开续聊、重命名和归档/取消归档。标题默认取首条用户提问，不调用模型生成。服务端列表返回最近20个非空会话，消息从最新50条开始，可加载更早内容。

## 存储与权限

复用 PostgreSQL 的 conversations / conversation_messages。启动时幂等增加 title、archived、purpose 字段及归属排序索引，不删除或重写消息。tenant_id + user_id + 当前数据库 schema 隔离，平台管理员无额外私聊读取权；新增 API 不绕过已有身份与 CSRF 校验。归档不是删除，归档后禁止新增问答，取消归档即可继续；未完成 Agent 任务不能归档。

浏览器 sessionStorage 只保存当前会话标识、草稿和侧栏状态，键包含用户与服务端工作区标识（数据库连接位置和实际 schema 的摘要，不含模型或集合）。历史列表和正文从服务端重读，刷新或更换模型不依赖 IndexedDB 的评测缓存。消息仍遵循已有引用权限检查；来源撤权/撤回后旧回答会被遮蔽。

Agent 历史打开时只读现有状态，GET 不启动任务、不调用模型，不自动提交提案或恢复执行。未完成任务显示现有操作入口，仍需用户主动确认；历史完成任务显示已保存答复和状态。

新产生的测试集评测会话标记 purpose=evaluation，不进入普通历史；此前未标记的非空会话仍保留显示，避免猜测并改写历史归属。完整聊天历史与发送给模型的上下文仍分离，沿用现有预算、摘要及追问恢复机制；不跨会话自动合并记忆。

## 接口

- GET /conversations：当前用户列表，limit、cursor、archived。
- PATCH /conversations/{id}：修改 title 或 archived。
- GET /conversations/{id}：保留原 after 分页，增加 latest=true 和 before 以读取最新/更早消息，返回标题、归档状态与分页信息。

后端重启后自动添加元数据字段，前端静态资源更新版本号。数据库继续使用原有 Docker 持久卷。按用户要求不运行自动化测试或付费模型验收，只检查启动状态，功能由用户验收。
