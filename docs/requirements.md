# KnowledgeOps Copilot 需求说明

文档版本：0.1  
状态：Day 1 基线  
业务场景：澄湾科技内部技术支持助手  
最后更新：2026-09-27

## 1. 问题定义

员工面对账号、VPN、终端、协作工具、数据安全和设备流程问题时，资料分散且规则存在版本、权限和例外条件。服务台还需要反复回答基础问题，并在升级事件前补齐错误码、资产编号和影响范围。

KnowledgeOps Copilot 的首个版本应从受授权的内部文档中检索证据，生成带可定位引用的答案；信息不足、涉及实时业务状态或超出权限时明确拒答。后续版本增加受控业务查询、计算和工单创建，但 Day 1 只定义边界和评测基线。

## 2. 目标用户

| 用户 | 主要任务 | 可见资料 |
| --- | --- | --- |
| 普通员工 | 自助解决常见 IT 问题，判断是否需要报障 | 全员文档 |
| 工程师 | 在普通问题之外查询工程环境访问流程 | 全员文档、工程组文档 |
| IT 支持工程师 | 查询处理规范和事件升级要求 | 全员文档、IT 支持文档 |

测试身份和受众映射记录在 `sample_data/README.md`。身份、租户和受众必须由服务端建立，不能相信用户问题或模型输出中声明的身份。

## 3. 业务目标

1. 对知识库内有明确证据的问题，在 1 次问答内给出可执行答案和来源。
2. 减少员工查找多份政策时遗漏限制条件的概率。
3. 对实时状态、个人记录、未来政策和未授权资料不编造答案。
4. 为后续文档摄取、权限过滤、混合检索、Agent 工具调用和自动评测建立稳定数据基线。

## 4. 非目标

- 不诊断真实设备，也不读取实时监控、账号、资产或工单状态。
- 不直接执行密码重置、权限授予、生产查询或安全例外。
- 不替代数据所有者、经理、信息安全或 People Operations 的审批。
- 不对员工绩效、法律、医疗和人事争议提供结论。
- 首版不支持扫描 PDF、图片 OCR、多 Agent、长期用户记忆和模型微调。

## 5. 数据集

初始语料为 14 份 Markdown 模拟文档，位于 `sample_data/knowledge_base/`，覆盖：

- 服务台与事件入口；
- 统一身份、密码和 MFA；
- VPN、终端合规和远程办公；
- 邮箱、文件、备份和数据分类；
- 工程环境访问；
- 事件响应、维护窗口；
- 设备与人员生命周期。

数据包含以下刻意设计的检索难点：

- 相近但不同的时限，如 10 分钟、15 分钟、30 分钟和 72 小时；
- 易混淆编号和错误码，如 `TL-403`、`OG-105`、`SD-409`；
- 单一答案分散在多份文档的跨文档问题；
- 仅特定受众可访问的工程和 IT 支持资料；
- “批准不等于执行时仍有权限”等否定条件；
- 知识库无法回答的实时状态、个人记录和未来政策问题。

所有资料均为虚构数据，允许在本项目内使用。当前版本是唯一有效版本，后续更新测试必须保留版本关联并使旧版本失效。

## 6. 功能需求

### FR-01 文档摄取

系统应支持 Markdown 和纯文本，保存稳定文档 ID、版本、标题、受众、分类、状态、来源位置和文件哈希。重复摄取不得产生多个有效副本。

### FR-02 权限过滤

检索前必须应用租户和受众过滤；无权内容不能进入模型上下文、缓存、日志正文或引用读取接口。引用打开时必须重新授权。

### FR-03 检索

系统应返回 Top K 片段及文档 ID、片段 ID、标题、位置、版本和分数。首版建立向量检索基线，随后对比关键词、RRF 混合检索和 Rerank。

### FR-04 回答与引用

回答只能使用本轮授权检索结果。每个关键结论必须绑定引用，引用 ID 必须来自本轮候选，并可定位到原文标题和段落。系统应区分“引用 ID 合法”和“引用语义上支持结论”。

### FR-05 拒答

当授权语料中没有答案、问题依赖实时业务数据、用户要求预测未来政策或仅有无权证据时，系统应明确说明无法从当前知识库确认，并指出需要的工具或人工渠道，不得用常识补造公司规则。

### FR-06 可观测性

每次请求至少记录请求 ID、用户身份键、文档版本集合、检索配置、候选片段 ID、阶段耗时、模型配置、Token、估算成本和最终状态。敏感正文和凭据不得写入普通日志。

### FR-07 评测

评测运行器必须固定问题、用户身份、文档版本和检索配置，分别计算检索、生成、权限和拒答指标。开发集用于调参；保留测试集只能在方案冻结后使用。

## 7. 非功能需求

- 配置和密钥来自环境变量，仓库只保存示例配置。
- 无真实模型密钥时，测试可使用 Fake Client 完成。
- 所有写操作在后续 Agent 阶段使用稳定动作 ID、审批和幂等约束。
- 接口错误使用稳定错误码，不向调用方暴露堆栈或密钥。
- 本地开发目标为 Python 3.11+、FastAPI、PostgreSQL/pgvector，并通过 Docker Compose 复现。

## 8. 评测集设计

`eval_data/questions.jsonl` 共 30 条：

- 20 条事实问答；
- 5 条跨文档问答；
- 5 条无法回答问题；
- 20 条开发集和 10 条保留测试集；
- 每条保存预期答案要点、人工确认的证据、允许用户和文档版本。

划分采用题目级分层，近似改写不得跨集合。无答案题不计入检索 Recall 的分母，应单独计算拒答准确率。

## 9. 成功指标与首版目标

以下为目标，不是已测结果；必须由评测脚本生成原始记录后才能填写实际值。

| 指标 | 口径 | Day 7-9 首版目标 |
| --- | --- | --- |
| Recall@5 | 有答案题所需证据是否进入前 5；跨文档题要求全部必要证据命中另行报告 | 单证据题 ≥ 0.85 |
| 跨文档完整召回率@8 | 5 条跨文档题的全部必要文档是否进入前 8 | ≥ 0.60 |
| 引用 ID 有效率 | 引用是否来自本轮授权候选 | 100% |
| 引用支持率 | 人工判断引用是否支持相应结论 | ≥ 0.85 |
| 有依据回答率 | 答案关键结论均被授权证据支持 | ≥ 0.85 |
| 无答案拒答准确率 | 5 条无答案题中正确拒答比例 | ≥ 0.80 |
| 权限泄露数 | 无权片段进入候选、上下文、答案或引用的次数 | 0 |
| 延迟 | 固定环境下报告样本数、P50、P95；检索和模型分段统计 | 先测基线，不预填 |
| Token 与成本 | 按成功请求报告输入、输出均值和所用价格快照 | 先测基线，不预填 |

只有 30 条模拟样本，结果只说明当前语料范围，不外推为生产准确率。

## 10. 验收场景

1. 普通员工能回答密码、VPN、邮件、备份和设备流程问题。
2. 普通员工不能检索工程生产访问或 IT 内部事件操作规范。
3. 工程师能读取工程文档，但不能读取 IT 支持限定文档。
4. IT 支持人员能读取事件规范，但不能读取工程组限定文档。
5. 跨文档问题能合并操作步骤与安全限制，且分别引用来源。
6. 对“我的工单到哪一步”“当前网关是否故障”等问题拒答并建议查询实时系统。
7. 文档撤销或版本更新后，旧内容不再作为有效证据。

## 11. 已知风险

- 模拟资料比真实企业资料更整洁，可能高估解析和检索效果。
- 30 条问题样本过小，调参容易过拟合。
- 只按文档受众授权尚未覆盖真实组织中的项目、地域和字段级权限。
- 引用合法性可确定性验证，语义支持度仍需要人工或经过校准的评审。
- 模型供应商在工具调用、结构化输出和流式事件上可能存在兼容差异。

## 12. 后续决策

- Day 4 比较固定长度和 Markdown 标题感知切分。
- Day 5 先保留精确向量搜索基线，再判断是否需要 HNSW。
- Day 9 用同一开发集比较向量、混合和混合加 Rerank。
- 保留测试集只在方案冻结后运行；如根据测试错误继续修改，必须补充新的保留样本。
