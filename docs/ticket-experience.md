# 工单预览、审批与详情

## 分类与业务审批

所有本地已登录身份默认可以提交本人、本租户的工单，无需先写入权限初始化记录。已有 can_write=false 的显式账号提交限制仍然有效，启动和业务数据升级不会恢复被撤销的权限。

服务端规则同时检查原始诉求与工单标题、描述：普通故障和标准补丁/已批准软件请求进入待受理；涉及权限、安全例外、生产变更的申请进入待业务审批；信息不足或否定、引用的敏感操作描述进入人工分诊；明确绕过审批、审计或越权的操作拒绝提交。混合诉求保留所有命中的审批能力，不按标题或模型自称“普通”放行。规则只是本地演示初筛，不是完整企业政策引擎；未接入任何实际操作执行器。

本地 IT 支持身份具备分诊、权限审批、安全例外审批与生产变更审批能力；其他身份没有审核能力。审核严格限定本租户并禁止自审，不按身份名称的高低决定。待分诊工单可人工归类；普通工单或已批准申请若出现新敏感操作，须升级审批，不能降级已有敏感范围。每次决策需要理由和版本，写入审核人、时间及状态变化；并发旧版本被拒绝。审批通过仅记录决策，状态为“审批通过 · 未执行”，不会改变设备或账号权限。

我的工单显示分类、业务状态与审计历史。IT 支持可使用“待我处理”入口审核其他申请人的工单；该入口只提供工单内容与审核信息，不暴露申请人的模型消息或知识引用轨迹。旧工单升级为待人工分诊，不补造历史业务审批。

## 使用路径

1. 后端重启加载新接口后，在首页“自动 · 问答与任务”模式输入：“我的 VPN 提示 TL-403，先查处理规则和我本人的模拟设备状态，再整理工单让我确认。”
2. 对话显示实际工具处理结果，可展开知识依据、查询结果与原始记录。缺失信息由 Agent 澄清，不预填虚构的资产编号或发生时间。
3. 出现工单预览后核对标题、描述。点击“修改内容”，保存后查看新版本；保存不会建单。脱敏后的内容会重新展示，确认以当前预览为准。
4. “确认提交”只提交当前版本，不是业务审批；“暂不提交”拒绝该提案；过期提案可取消任务后重新发起。提交仍检查显式账号限制，禁止操作由服务端拦截。
5. 成功回执显示工单编号、提交时间及内容，点击“查看工单详情”。导航栏“我的工单”可以重新打开已提交记录。
6. 工单详情显示最终内容、创建时间、批准版本、处理/审批时间线和建单前依据。历史工单优先从已保存的提交事件读取时间；确无时间时显示缺失，不补造。

工单记录本地提交、分诊和业务审批，没有新增实际派单、执行、解决或关闭能力。创建成功后 Agent 最终回复失败/中断，仍保留成功回执与详情。普通读取接口仍只允许读取本人、本租户工单；审核接口按对应能力限制访问。详情原文按钮继续走引用权限检查。

## 接口

- GET /workbench/tickets：我的工单页面。
- GET /workbench/tickets/{ticket_id}：可直接访问/刷新的详情页。
- GET /tickets?limit=30&offset=0：当前身份工单列表。
- GET /tickets/{ticket_id}：当前身份单条详情，无权读取返回404。
- POST /agent/{run_id}/proposal：传入 action_id、旧version、旧digest和arguments（title、description）；保存新版本，返回待审批状态，不启动模型、不写入工单。
- 现有 POST /agent/{run_id}/approval：申请人确认提交或放弃当前具体版本，不是业务审批。
- GET /ticket-reviews：当前审核人有权处理的本租户队列，不含本人申请。
- GET /ticket-reviews/{ticket_id}：审核详情，不包含原始模型消息和工具轨迹。
- POST /ticket-reviews/{ticket_id}/decisions：传入 action、version、reason；triage/escalate 还需 category。action 为 triage、approve、reject、escalate。

提案修改与提交使用同一个任务行锁和动作行锁；修改后重新分类、计算摘要，旧摘要失效。提交继续使用原有事务、唯一 action_id 和显式账号限制。业务审批使用独立 ko_ticket_workflows 表的版本和行锁，历史审核不与用户的提交确认混淆。应用初始化会创建该表并将旧工单置为待分诊。

## 验证状态

验证包括前端组件、过期退出分支、工单预览编辑、分类与审批的数据库集成测试。真实供应商及真实设备操作不在验收范围内。新增后端接口需要重启服务；仅修改静态前端无需重启。界面配置的密钥按现有设计仅保存在服务端内存中。

4 个数据库回归用例覆盖以下场景，位于 tests/integration/test_persistent_agent.py：
- 修改使旧审批失效，批准新版本后只提交一次，内容与详情一致。
- 不同用户和租户不能修改或读取工单。
- 并发编辑只允许一个版本前进，过期提案不能修改。
- 已取消提案不能编辑。

测试集 manual-agent-cases.md 的 A009 已更新为实际编辑界面流程，可结合 A006（拒绝）和 A011（确认建单）手工验证。
