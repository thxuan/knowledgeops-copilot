# 我的业务状态

本次增加一个轻量业务入口，保留三类记录，不增加组织管理、复杂资产台账或派单系统。

| 类别 | 字段与用途 |
| --- | --- |
| 设备与合规 | 资产编号、操作系统、受管状态、合规结果和原因、补丁、EDR、磁盘加密、快照时间 |
| 账号与安全 | OneGate启用状态、已登记MFA类型与数量、普通访问范围、临时PRD权限及到期时间 |
| 工单进度 | 本人批准创建的本地工单、提交时间、当前状态、处理人和预计完成时间 |

设备和账号为固定演示快照，界面刷新只读取数据库。历史记录缺少检查结果时显示“未知/未记录”，不会根据整体不合规猜测EDR离线或磁盘未加密。补充演示字段时保留已有业务值和撤销的写权限。

工单状态来自持久化审批记录，仅已提交动作会被查询到。当前没有派单/处理系统，因此状态为已创建（待分配），处理人为null，预计完成时间为null。未来接入工单系统后可扩展，当前不得假称已派单或已解决。

原12+28分钟、目标60分钟的耗时数据保留在折叠区域，明确为独立演示记录，不对应新建工单。

## 使用

打开 /workbench/business，导航栏为“我的业务状态”。可以切换工程师、普通员工和IT支持查看各自记录。点击“让Agent分析”会进入会话并填入固定任务，用户点击发送才调用模型；查询、分析、提案、审批流程保持原有边界。

- 查询我本人的设备状态，结合公司政策说明合规问题。
- 查询我的OneGate账号安全状态，核对MFA要求。
- 查询我最近提交的模拟工单，缺少处理人和预计完成时间时明确说明。
- 查询工单ID为……的状态（仅本人实际已提交工单）。
- 查询独立工单耗时示例，并计算是否超过目标。

query_business_data支持device_status、account_status、ticket_status、ticket_durations。ticket_id可选且仅适用于ticket_status；未指定时返回最新10条及本人总数。接口不接受用户指定身份或SQL。

GET /business/overview返回当前身份的四个分区；缺少某类记录只显示该分区暂无记录。页面 /workbench/business 不需要模型配置即可读取业务数据，但需要有效的只读数据库连接。

## 数据初始化与权限

scripts/setup_agent_demo.py新增--business-only参数，可补齐演示业务记录及只读视图授权，不创建或恢复建单权限。重复执行保留已有业务值。自定义数据库需显式传入--database-url。

ko_ticket_business为受限视图，只投影工单状态字段，不向业务只读账号授权原始模型消息、审批摘要或工具轨迹表。查询始终过滤tenant_id与user_id。scripts/workbench.py对项目标准本地演示数据库使用已有knowledgeops_agent_reader；自定义数据库应配置KNOWLEDGEOPS_AGENT_BUSINESS_DATABASE_URL。

演示业务记录通过初始化脚本补充，初始化不运行模型、创建 Agent 任务或提交工单。

## 手工验收

1. 工程师页面有设备、账号、工单三个区域；缺失字段不会伪装成通过。
2. 切换身份后清空旧画面再读取新数据；另一身份不能读取本人指定工单。
3. 账号分析能调用account_status并检索OneGate政策；不能声称已替用户补绑MFA。
4. 待审批提案不出现在工单状态；批准后工单才出现在列表，详情ID一致。
5. 工单没有处理人/预计完成时间时明确显示未分配/未提供。
6. 从业务页进入会话时只填入任务，不自动发送；即使之前浏览评测视图也切回会话。

数据库回归用例位于 tests/integration/test_persistent_agent.py。原问答测试集U005仍是“仅知识问答无法获知工单实时信息”的边界题；Agent模式现在可以查询本人实际提交工单。
