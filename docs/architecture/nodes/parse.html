01 / RESPONSIBILITY

这个节点接收什么，交付什么？

INPUT / 输入

PostgreSQL 中待处理任务、原始文件字节、解析配置。

OUTPUT / 输出

清洗后的 text、title、metadata，以及 succeeded / failed 任务状态。

02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    领取任务

    IngestionWorker 轮询数据库，claim 领取任务并记录租约和领取 token；数据库任务才是事实来源。

  2. 02

    解析与清洗

    parse_document 解析 Markdown/TXT；clean_document 规范正文。阶段推进、完成和失败都经仓储写入。

  3. 03

    故障恢复

    过期租约任务可重新领取；任务查询保留阶段和错误原因。失败可通过 retry 接口在次数上限内重试。

故障路径
worker 中断 → 租约过期 → 重新 claim
解析错误 → failed + error_code
POST /ingestion/tasks/{task_id}/retry → 再次调度

04 / DESIGN BOUNDARIES

需要讲清的设计边界

过期执行器不能覆盖结果

advance / complete 使用领取 token 检查任务所有权，避免新旧 worker 同时提交。

本地轮询，不是消息队列

当前由 FastAPI lifespan 启动 worker，没有 Redis / Celery 队列，也没有 PDF 或 OCR 解析。

05 / TERMINOLOGY

专业术语 · 中英全名

中文 / 缩写英文全名在项目中的含义
租约Lease有时间期限的执行权；租约 token 隔离已失去执行权的旧执行器。
检查点Checkpoint持久化运行消息、阶段、预算与结果，供同一个 run_id 恢复执行。
OCR · 光学字符识别Optical Character Recognition把扫描图片转为文本；当前摄取只接受 Markdown/TXT，未实现 PDF/OCR。
