INPUT / 输入

chunk_id、chunk_set_id 与当前访问身份；文档更新需要 expected_version。

OUTPUT / 输出

引用正文与来源位置，或对不可见／过期证据返回 404。

02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    生成可追踪引用

    make_citation 从片段构造文档、来源、版本、标题路径、字符和行号信息，携带切分集合 ID。

  2. 02

    读取时重新鉴权

    citation 连接当前文档头、ACL、active 标记与解析成功状态；旧链接不能绕过新权限。

  3. 03

    文档更新主动失效

    update 校验所有者和 expected_version，更新正文与 revision，并删除旧 document_chunk_heads；重新切分和索引前不可继续检索旧版本。

追溯原文
GET /citations/{chunk_id}?chunk_set_id={chunk_set_id}
→ 正文 + 来源 + 版本 + 位置
权限撤销 / 版本更新 / 集合切换
→ 旧引用不可继续读取

04 / DESIGN BOUNDARIES

需要讲清的设计边界

当前实现有重建窗口

不是目标架构中的新版本索引完成后无缝切换。更新先失效旧头，再显式重建；这避免旧证据被当成当前资料。

删除为逻辑删除

active=0 并移除当前头；旧向量可能仍在物理表中，但有效集合过滤阻止它进入查询。

05 / TERMINOLOGY

专业术语 · 中英全名

中文 / 缩写英文全名在项目中的含义
来源引用Citation绑定文档、版本、chunk_set_id、chunk_id 与位置；读取时重新检查当前权限。
ACL · 访问控制列表Access Control Listdocument_access 保存文档到用户的授权；身份和租户由服务端映射。
文本分块Text Chunk / Chunking把清洗后的正文切成带来源位置的片段；当前 size 和 overlap 的单位是字符。
数据库事务Database Transaction将本地工单、动作结果和任务回填一并提交或回滚，避免只成功一半。
