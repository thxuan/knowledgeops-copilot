02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    PostgreSQL：文档与会话

    IngestionRepository 管理 documents / ingestion_jobs / 任务事件；ChunkRepository 管理 chunk_sets / chunks / document_chunk_heads；ConversationRepository 管理 conversations / conversation_messages。

  2. 02

    PostgreSQL：向量

    VectorRepository 管理 ko_collections、ko_documents、ko_chunks、ko_embeddings、ko_vector_heads、ko_embedding_batches，pgvector 提供向量存储和索引。

  3. 03

    PostgreSQL：Agent

    ko_agent_runs 的 JSONB state 保存消息、轨迹、事件和预算；actions、tickets、permissions、business 分别承担动作、工单、权限和模拟数据。

  4. 04

    用当前头连接元数据与向量表

    检索先从 PostgreSQL 得到可见的 document_id / chunk_set_id，再要求 PostgreSQL 返回对应的当前索引内容。

数据归属
PostgreSQL        文档 / ACL / 切分头 / 会话
PostgreSQL    向量 / 向量头 / Embedding 批次
PostgreSQL    Agent 任务 / 动作 / 工单 / 权限
SELECT-only   模拟业务查询连接

04 / DESIGN BOUNDARIES

需要讲清的设计边界

配置项可以指向同一 PostgreSQL

向量连接和 Agent 连接分开配置；业务读取另用只读账号。逻辑仓储边界不意味着部署了三个数据库服务。

无分布式事务

文档更新先令旧头失效；索引发布与工单提交分别在各自事务内原子完成。运行日志不能代替业务事实记录。

05 / TERMINOLOGY

专业术语 · 中英全名

中文 / 缩写英文全名在项目中的含义
SQL · 结构化查询语言Structured Query Language业务工具执行预定义的参数化查询，不接受模型生成的任意 SQL。
JSONB · 二进制 JSON 数据类型Binary JSONPostgreSQL 用来保存 Agent state、参数与结果的数据类型。
数据库事务Database Transaction将本地工单、动作结果和任务回填一并提交或回滚，避免只成功一半。
检查点Checkpoint持久化运行消息、阶段、预算与结果，供同一个 run_id 恢复执行。
