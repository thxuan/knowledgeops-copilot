INPUT / 输入

OUTPUT / 输出

02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    选择切分策略

    支持 fixed 和 structure。结构切分识别 Markdown 标题层级与段落边界，并避免把代码围栏内的标题标记当成正文标题。

  2. 02

    保留来源坐标

    Chunk 保存标题路径、字符区间、行号、前后邻接、来源版本、文本哈希与配置 ID。坐标相对清洗正文。

  3. 03

    原子切换集合

    先计算全部块，再开启 PostgreSQL 事务锁定文档行并复核 revision，写入完整集合并切换 document_chunk_heads。

请求示意
POST /documents/{document_id}/chunks
{"strategy":"structure","size":400,"overlap":0}
→ length_unit: character
→ coordinate_system: cleaned_body:zero_based_half_open

04 / DESIGN BOUNDARIES

需要讲清的设计边界

长度单位是字符

默认结构切分 size=400、overlap=0；不是 400 Token。字符位置为从 0 开始的半开区间。

切分改变会使旧索引不再匹配

检索必须匹配当前 chunk_set_id；新集合还需调用 index 建立对应向量。

05 / TERMINOLOGY

中文 / 缩写英文全名在项目中的含义
文本分块Text Chunk / Chunking把清洗后的正文切成带来源位置的片段；当前 size 和 overlap 的单位是字符。
词元Token模型处理和计费的文本单位；项目的 UTF-8 字节预算是保守估算，不等于真实账单词元。
