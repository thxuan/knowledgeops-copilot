02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    定义数据与标注

    RAG 以 20 条开发集、10 条保留集组织；先验证来源与章节标注，避免标注缺失污染评测或浪费模型调用。

  2. 02

    分别度量检索和生成

    检索统计来源 Recall、MRR、章节覆盖与过滤；生成记录拒答、引用有效率、延迟与 usage；语义正确性和引用支持度需复核标签。

  3. 03

    Agent 验证最终环境

    10 个脚本场景各重复 3 次，检查轨迹和工单最终数量，覆盖工具失败、拒绝审批、重复、恢复和权限撤销等。

  4. 04

    按阶段定位失败

    从解析→切分→召回→上下文→生成逐层检查；业务任务另检查审批、事务和最终表状态。实验保留配置、逐条结果与已知限制。

05 / TERMINOLOGY

专业术语 · 中英全名

中文 / 缩写英文全名在项目中的含义
前 K 项召回率Recall at K在预先标注的相关来源中，前 K 个结果命中了多少；无答案样本单独统计。
MRR · 平均倒数排名Mean Reciprocal Rank对首个相关结果排名取倒数再求平均，用于衡量相关证据出现得是否靠前。
第 95 百分位延迟95th Percentile Latency95% 样本的延迟不超过此值；P50 为第 50 百分位，小样本尾部估计不稳定。
TTFT · 首词元时间Time to First Token供应商首个输出词元的时间；当前 Agent 文本在完整校验后分段发送，不能算真实 TTFT。
执行轨迹Execution Trace记录工具调用、状态、耗时及结果；日志用于诊断，检查点和事务负责恢复与副作用。
