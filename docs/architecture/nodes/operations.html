02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    两种请求生命周期

    ChatAdmission 在单进程内限制 /chat 并发和速率，断连尽量取消上游；Agent 采用持久化任务、数据库限速与租约并发控制。

  2. 02

    有界执行

    Agent 限步骤、总耗时、上下文、Token、费用与工具输出大小；每次重试前预留预算，不因未知结果退还。

  3. 03

    执行层安全

    工具白名单、严格参数、服务端身份、授权检索、只读查询与人工审批构成防线。注入检测只做告警，脱敏只覆盖部分常见格式。

  4. 04

    当前启动形态

    scripts/demo.py 提供固定 Fake 的初始化、启动、验证与评测；docker-compose.demo.yml 追加本地 API 容器；GitHub Actions 已配置但待远端首次运行。生产认证与云端性能尚未验证。

排障顺序
先看 request_id / run_id
→ status + phase + outcome
→ trace / usage / events
→ 依赖配置、权限、租约、预算
→ 最后确认业务工单是否已提交

04 / DESIGN BOUNDARIES

需要讲清的设计边界

可观测不等于可恢复

日志记录请求与耗时，trace 解释动作；Checkpoint 和业务事务才支持恢复与幂等。

不要把规划组件画成在线组件

Redis、LangGraph、MCP、OpenTelemetry 都不是当前主链路依赖；缓存与生产认证也未实现。

05 / TERMINOLOGY

专业术语 · 中英全名

中文 / 缩写英文全名在项目中的含义
执行轨迹Execution Trace记录工具调用、状态、耗时及结果；日志用于诊断，检查点和事务负责恢复与副作用。
指数退避与抖动Exponential Backoff and Jitter瞬时错误有界重试，逐步增加等待并加入随机扰动，避免同时重试。
提示词注入Prompt Injection用户、文档或工具结果试图改变系统行为；检测告警与实际授权防线分开。
CI · 持续集成Continuous Integration计划 Day 13 的自动化检查；当前有 pytest 测试，未发现 CI 工作流。
MCP · 模型上下文协议Model Context Protocol计划中的可选工具接入协议，当前代码没有实现 MCP 服务。
TTFT · 首词元时间Time to First Token供应商首个输出词元的时间；当前 Agent 文本在完整校验后分段发送，不能算真实 TTFT。
