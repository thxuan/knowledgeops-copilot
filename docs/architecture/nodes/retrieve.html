02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    限定候选范围

    allowed_sets 读取 PostgreSQL 中租户、用户 ACL、active 文档、成功解析状态和当前切分头；PostgreSQL 查询只在匹配集合内进行。

  2. 02

    向量与关键词召回

    先做 query Embedding 和向量搜索，再按需要读取授权语料运行 BM25。中文使用二元字组，英文保留产品编号等标识符。当前 prepare 顺序执行两路。

  3. 03

    融合并选择候选

    RRF 按排名求和，而不是相加余弦与 BM25 原始分数。融合结果先截为 candidate_k。

  4. 04

    可选重排与最终复核

    hybrid_rerank 调用重排适配器，异常回退融合排名；外部调用之后再次校验授权，再截为 top_k 并返回。

三种模式
vector        → 向量候选 → Top K
hybrid        → 向量 + BM25 → RRF → Top K
hybrid_rerank → 向量 + BM25 → RRF → Rerank → Top K

04 / DESIGN BOUNDARIES

需要讲清的设计边界

当前选择 hybrid

Day 9 冻结配置：candidate_k=20、top_k=5、RRF 常数 60、重排关闭。没有环境设置时 Python 回退策略仍是 vector。

检索不是答案质量证明

05 / TERMINOLOGY

专业术语 · 中英全名

中文 / 缩写英文全名在项目中的含义
BM25 · 最佳匹配 25Best Matching 25关键词相关性排序；当前使用中文二元字组与英文标识符分词，仅统计授权语料。
RRF · 倒数排名融合Reciprocal Rank Fusion对每一路的 1 / (常数 + 排名) 求和，融合向量和关键词结果；不直接相加原始分数。
重排序Reranking对召回候选再次排序；已实现，可选启用，冻结的 hybrid 配置关闭它。
前 K 个结果Top K Resultscandidate_k 控制候选池，top_k 控制最终结果；两者不是同一层的参数。
ACL · 访问控制列表Access Control Listdocument_access 保存文档到用户的授权；身份和租户由服务端映射。
HNSW · 分层可导航小世界图Hierarchical Navigable Small Worldpgvector 的近似向量索引；本项目也保留精确搜索作为基线。
