01 / RESPONSIBILITY

这个节点接收什么，交付什么？

INPUT / 输入

Markdown / TXT 文件、source、version，以及服务端 Identity。

OUTPUT / 输出

HTTP 202；document_id、task_id 与当前处理状态。

02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    验证上传

    read_upload 去掉文件路径，只接受 .md / .txt；有界读取 max_bytes + 1，拦截空文件与超限文件。

  2. 02

    计算去重标识

    receive 使用 SHA-256 文件哈希并附解析器版本；唯一键为租户、文件哈希和解析器版本。复用既有文档时还必须通过当前用户 ACL 检查。

  3. 03

    先落库再返回

    原始内容、documents 与 ingestion_jobs 写入 PostgreSQL。返回的任务可以随后查询，即使解析尚未开始。

操作顺序
POST /documents
→ 202 + document_id + task_id
→ GET /ingestion/tasks/{task_id}
→ succeeded 后调用 /documents/{document_id}/chunks

04 / DESIGN BOUNDARIES

需要讲清的设计边界

不要把 202 当成完成

它只表示任务已受理；即使之后 succeeded，也只代表解析清洗完成，切分和索引需要另行触发。

身份由服务端决定

X-Local-User-Id 只用于本地演示映射；文档元数据不能为上传者授予额外权限。
