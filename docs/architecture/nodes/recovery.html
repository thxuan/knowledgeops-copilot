01 / RESPONSIBILITY

这个节点接收什么，交付什么？

INPUT / 输入

原 run_id、租约 token、持久化 phase / messages / events；事件游标。

OUTPUT / 输出

02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    领取与隔离执行权

    claim 使用数据库锁与全局活跃租约计数限并发；checkpoint 必须持有当前未过期 token，取消或接管会隔离旧执行器。

  2. 02

    按检查点继续

    模型请求已保存后再执行工具；恢复只重放尚无结果的只读调用。预算随任务保存，硬崩溃后的墙钟时间也计入。

  3. 03

    显式恢复或取消

    POST /resume 重启原任务执行，waiting_approval 不能被绕过；POST /cancel 转换终态并释放执行权。没有后台自动扫描积压队列。

  4. 04

    补发持久化事件

    GET /events 用 after 或 Last-Event-ID 过滤已保存事件。断开事件流不取消任务；重新订阅不创建新任务。

状态轨迹
running / queued → running / model → running / tools
→ waiting_approval / approval
批准 → running / after_commit → completed
拒绝 → cancelled；执行异常 → failed

04 / DESIGN BOUNDARIES

需要讲清的设计边界

queued 是 phase

刚创建时 status=running、phase=queued；不能把 queued 当成新增 status 枚举。完成、失败、取消才是终态。

SSE 不是真实词元流

text_delta 在完整答案校验后按 120 字符切片，TTFT 未测。恢复可能再次调用模型或只读工具，不保证无重复计费。

05 / TERMINOLOGY

专业术语 · 中英全名

中文 / 缩写英文全名在项目中的含义
检查点Checkpoint持久化运行消息、阶段、预算与结果，供同一个 run_id 恢复执行。
租约Lease有时间期限的执行权；租约 token 隔离已失去执行权的旧执行器。
SSE · 服务器发送事件Server-Sent Events服务端单向事件流；通过持久化事件 ID 支持补发，不创建新任务。
TTFT · 首词元时间Time to First Token供应商首个输出词元的时间；当前 Agent 文本在完整校验后分段发送，不能算真实 TTFT。
幂等性Idempotency相同请求键复用任务，相同 action_id 不重复创建工单。
