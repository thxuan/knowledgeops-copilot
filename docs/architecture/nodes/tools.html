OUTPUT / 输出

02 / EXECUTION FLOW

代码是怎样一步步执行的？

  1. 01

    知识搜索

    search_knowledge_base 复用 RetrievalService，返回 untrusted_evidence 和来源；未配置检索服务时明确失败。

  2. 02

    计算器

    calculator 使用 Decimal 和运算符白名单执行受限算术，不运行模型提供的表达式代码。

  3. 03

    受限业务查询

    query_business_data 只允许既定查询枚举，以服务端租户和用户过滤。使用 SELECT-only 独立账号、只读事务与语句超时。

  4. 04

    工单提议

    create_ticket 必须独占当前调用批次，进入审批仓储；read_tool 不直接写工单。最多四个同轮独立只读调用可并行。

并行与依赖
同轮：知识搜索 || 本人设备状态查询
→ 两个独立结果共同回填
下一轮：使用查询值调用计算器
→ 有数据依赖的动作不能提前并行猜参数

04 / DESIGN BOUNDARIES

需要讲清的设计边界

参数合法仍需要授权

模型不能传入任意用户身份或 SQL；数据库参数化、只读账号与行级条件分别承担不同职责。

结果不可信且有上限

工具输出做基本脱敏，最大 18000 UTF-8 字节；超出则失败而非截断证据。知识工具文字引用不等于 RAG 逐条 Claim 校验。
