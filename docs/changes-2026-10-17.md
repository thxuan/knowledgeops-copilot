# 2026-10-17 工作台与工单流程更新

## 界面与会话交互

- 统一会话、知识库、工单、业务状态和连接设置的导航及浅色玻璃主题，兼顾移动端与减少透明度偏好。
- 收拢调试入口，优化欢迎区、输入框、知识库原文/切块切换和连接设置的保存状态提示。
- 回答参考来源、任务处理记录与详情统一放在正文下方，支持折叠查看。
- 消息滚动尊重用户阅读位置，提供“回到最新”；知识问答支持停止生成、失败重试和输入法组合输入。
- 取消任务、放弃提交或关闭过期预览成功后清空当前对话与草稿，开启空会话；取消失败不清空。审计记录及已创建工单保留。

## 多轮会话与评测

- 自由会话与测试集评测分开统计，按会话、轮次、尝试展示自由记录；工具调用和任务轮询不额外增加轮数。
- 失败、停止和重跑保留独立尝试，支持本地缓存恢复、逐条评审与 JSON 导出。
- 服务端保存按租户和用户隔离的历史提问与摘要快照；原上下文重跑固定原问题与历史，不改写或追加原会话，也不重新执行任务工具。
- 对比核验历史指纹、身份和知识库版本；缺少快照的旧记录不冒充原上下文重跑。重跑仍重新检索并检查当前证据权限。

## 工单提交、分诊与审批

- 已登录身份默认可提交本人工单，无需预先初始化授权记录；显式禁止提交的账号限制仍有效。
- 服务端结合原始诉求及工单内容进行保守规则初筛：普通故障、标准服务请求、敏感申请、待人工分诊、禁止操作。
- 申请人确认提交不等于业务批准；普通请求待受理，敏感申请待对应能力审批，含糊请求待分诊，明确禁止操作拒绝提交。
- 经用户明确授权，内置 IT 支持身份具备分诊、权限申请、安全例外和生产变更四项审核能力；能力独立于知识库访问组。
- 新增“待我处理”队列、分诊、批准、拒绝和升级审批，校验租户、非本人及所需全部能力；决策需要理由与版本并保留审计历史。
- 审批通过仅记录决策，不会执行设备、账号或生产变更；旧工单升级为待人工分诊，不补造业务批准。

## 启用与边界

- 后端启动时初始化 `workbench_contexts` 和 `ko_ticket_workflows`；部署时需先备份数据库并确保建表权限。
- 后端改动需重启，静态资源刷新即可；现有模型、Embedding 和其他连接配置可能仅存于服务内存，重启前应准备恢复。
- 工单规则是本地演示初筛，不是完整企业政策引擎；没有新增真实派单或执行器。内置身份切换仍是本地演示机制，不是生产认证。
- 新增测试覆盖会话分组、取消清屏、滚动与停止控制、历史快照重跑、工单分类、禁止自审、权限隔离、并发版本及提交幂等。

详细行为见 [会话界面](chat-interface.md) 与 [工单流程](ticket-experience.md)。
