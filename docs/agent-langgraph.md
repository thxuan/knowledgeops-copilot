# Agent 与第三阶段验收

2026-10-22：当前实现已使用 create_agent，12 项关键离线检查通过，用户已确认业务验收通过。第二阶段长会话记忆尚未开始。

## 执行职责

`app/agent/service.py` 调用 langchain.agents.create_agent，由标准 Agent 提供模型/工具循环、工具分派和框架消息状态；底层 LangGraph 同步保存检查点。原自定义 graph.py 已移除。业务规则集中在 `app/agent/middleware.py`：

| 扩展点 | 职责 |
| --- | --- |
| awrap_model_call | 每次付费请求前持久预留预算，有界重试，校验工具批次、参数、输出与用量；保存模型回执 |
| awrap_tool_call | 复用工具回执、检索费用预留、只读工具重试与审计；工单提交确认暂停和恢复 |
| abefore_agent | 尚无新框架检查点的旧工具待执行任务，直接进入框架 tools 节点 |
| aafter_model | 最终格式修复回到框架 model 节点；已验证最终回答结束执行 |

`app/agent/chat_model.py` 提供单轮 BaseChatModel 桥接，保留第一阶段 ChatOpenAI 的兼容供应商协议、错误与用量处理。`app/agent/tools.py` 注册计算、知识检索、业务查询和工单回执四个 StructuredTool，服务端绑定身份。

## 工单确认

模型只能提议工单。工具 middleware 持久化待确认动作并调用 interrupt 暂停；原确认 API 检查 action_id/version/digest、当前权限与有效期，并在事务内提交工单。相同 run_id 使用 Command(resume=True) 唤醒后，middleware 验证服务端已提交回执，将实际批准参数传给工具；工具仅返回已有结果。编辑后的参数也会进入模型上下文。

审批绑定、幂等事务、独立 IT 支持业务审批和 HTTP/SSE 契约保持原有职责。框架 resume 值本身不授予写权限。

## 检查点与恢复

- `ko_agent_graph_checkpoints` 保存框架消息状态、通道版本和父检查点；`ko_agent_graph_writes` 保存节点输出与中断。沿用已有 PostgreSQL 存储，create-agent-v1: 命名空间区分当前实现与旧显式图。
- `app/db/agent_checkpoints.py` 是受服务端身份与租约约束的 BaseCheckpointSaver。取消或租约失效后，旧工作者无法写回框架检查点。序列化关闭 pickle，仅允许必要的框架消息和 Interrupt 类型。
- `ko_agent_runs` 保留事务业务事实、API 视图、费用和审计。模型调用使用该账本中的最新批准参数和业务上下文；框架消息负责标准执行循环。内部模型回执和已有工具 trace 防止保存窗口中的重复执行，不通过公开 API 返回内部模型回执。
- 旧图检查点保留。无新框架检查点时，从业务历史接续旧任务；待执行工具经 framework tools 节点处理，已提交工单不重复创建。
- 查看历史或 GET/SSE 不启动执行；运行中任务通过原 resume 接口显式恢复。待确认动作仍需人工确认。
- 供应商已收到请求但结果尚未持久化时崩溃，恢复可能再次调用模型；原预留预算继续计入。工单依靠 action_id 唯一约束与事务保证幂等。
- 检查点不保存 API Key、数据库 DSN 或租约 token；业务全量恢复仍需 PostgreSQL 备份。

## 用户验收

在连接设置中恢复真实模型与输入/输出单价；需要文档检索时，也配置 Embedding 与单价。原有索引无需重建。

1. 查询本人设备、账号状态，执行依赖查询结果的计算，核对工具过程和最终回答。
2. 请求创建工单，确认提案出现时没有提前建单；修改内容后确认，核对工单与批准版本一致。
3. 在待确认时重启服务，恢复相同模型与单价，再确认原提案；核对同一任务继续且只存在一张工单。
4. 取消运行中任务，刷新历史，核对不再继续输出成功或产生后续写入。
5. 核对敏感工单仍进入对应 IT 支持业务审批队列；提交确认不代表敏感操作已获批准或执行。
