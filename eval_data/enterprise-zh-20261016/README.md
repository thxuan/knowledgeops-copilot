# 当前企业中文知识库测试集

基于2026-10-16工作台实际入库、已索引的文档整理。当前数据库空间为 `ko_samples`，Embedding 集合为 `bailian-v4-1024-validation-v1`。55份文档中工程师可见54份；本套问答覆盖这54份。参考答案来自当前解析正文，未调用模型、检索评测或 Agent。

## 文件与覆盖

| 文件 | 用途 |
| --- | --- |
| engineer-smoke.jsonl | 12题快速检查：4道技术题、2道政策题、4道跨文档题、2道不可回答题 |
| engineer-qa.jsonl | 完整80题，前端可直接导入 |
| reference-answers.md | 全部问题、人工参考要点和原文摘录 |
| manual-agent-cases.md | 12项 Agent 手工测试步骤与验收条件 |
| manual-agent-cases.jsonl | 同一批手工场景的结构化版本，不是前端问答导入格式 |
| corpus-manifest.json | 来源、版本、正文哈希、解析器、ACL、原始署名与题号覆盖 |
| validation-report.json | 本次静态格式与坐标校验结果；不是模型质量结果 |

完整问答：G001–G041为41道GNOME单文档题；P001–P013为13道企业政策题；X001–X016为16道跨文档题；U001–U010为10道不可回答题。共70道有答案题、10道不可回答题，嵌入224处原文坐标。

跨文档题重点检查：桌面通用建议与企业具体政策的适用范围、本机账号与企业身份、备份方法与公司备份制度、功能可用与实际授权之间的区别。不可回答题检查实时状态缺失、秘密索取、平台不适用以及声称完成不存在的操作。

## 前端使用

1. 打开工作台，使用**工程师**身份 `u_engineer_001`，保持上述数据库空间和集合。
2. 在“评测与运行记录”的“测试集”中点“导入 JSONL”，选择 `engineer-smoke.jsonl`。章节坐标已嵌入题目文件，可选坐标文件留空。
3. 导入只校验文件；确认模型与检索参数后，由你点击“开始评测”。随后可换成完整的 `engineer-qa.jsonl`。
4. 对照 `reference-answers.md` 人工评审答案。快速集是完整集的子集，运行两份会重复这12题。
5. 验证 Agent 时切回自由对话，选择“自动 · 问答与任务”，按 `manual-agent-cases.md` 操作。前端批量问答不会执行建单、审批、恢复等 Agent 流程。

全部题目的 `split` 为 `dev`，用于当前调参与验收，不作为盲测成绩。批量运行按实际配置调用模型并产生相应费用；静态校验不包含模型调用。

## 权限与快照约定

- 工程师当前可见41篇GNOME指南和13篇企业政策。仅IT支持可见的 `07-incident-priority-and-escalation.md` 没有纳入本套问答。
- 新上传的41篇GNOME指南当前仅工程师可见；`06-engineering-access.md` 也仅工程师可见。因此所有问答标记 `allowed_user_ids: ["u_engineer_001"]`；该字段只筛选题目，不会给用户授予文档权限。
- 如要验证权限隔离，可在自由对话切换普通员工/IT支持，检查不返回无权文档的原文和引用。不要把完整工程师题集的缺失引用直接计为这些身份的检索失败。
- `expected_sources` 使用当前数据库真实的source和version。GNOME文件经前端上传后source是文件名，而不是官网URL；官网地址另列在manifest。
- `source_spans` 是解析后正文的Unicode字符区间，左闭右开；哈希为正文UTF-8的SHA-256，附解析器版本。不是上传文件含front matter时的原始偏移，也不是UTF-8字节偏移。
- 题目文件与切分配置相互独立。仅改变chunk大小且正文/解析器/source/version/权限保持不变时，原文坐标仍能使用。更换正文、解析器、source、版本、重复上传形成歧义，或更改ACL后，需要重新核对标注。
- runtime_fingerprint仅记录制作时配置以便复盘，不限制你之后比较检索参数；不同配置的结果应分别记录。

## 如何判断结果

前端可按有标注的70题计算来源召回、跨文档来源完整性、章节精确率与字符覆盖率。它们反映检索证据，**不等于答案正确率**。必要来源标注按该题全部问题整理；少引用某一必要来源应检查回答是否真的覆盖所有问题。

答案可逐题记0/1/2分：0为错误、捏造或越权；1为主要方向正确但缺少关键要点；2为关键要点齐全且引用支持。先分别统计技术题、政策题、跨文档题，不可回答题单独统计是否正确承认信息或能力不足。U题没有必要来源标注，前端显示检索指标不可用是预期现象，回答仍需人工评审。

Agent按步骤和验收条件判定，不一律要求completed：澄清为status=completed、outcome=needs_clarification；拒绝审批为status=cancelled、outcome=rejected；参数摘要或权限校验失败可能保持waiting_approval并返回错误。具体见手工场景。建单只验证本地模拟工单，不代表已修复终端、改密或授予生产权限。

## 来源与许可

GNOME官方中文内容、相应摘录和改编按CC BY-SA 3.0提供；逐篇官网URL、原始作者/译者署名及许可证记录在 `corpus-manifest.json`，原知识文档也保留来源与处理说明。企业政策是项目本地虚构数据，不代表真实企业规定。许可范围不改变项目代码原有许可。

已知原文边界：GNOME硬件指南的PCI段落命令存在疑点，本集G028只采用网络设备和USB检测段落；移除驱动器页面某个标题与安全弹出正文不一致，G011按正文测试安全弹出，不把它解释为格式化指令。密码等通用建议可能与公司政策不同，X001等题专门检验适用范围。没有修改知识库原文。
